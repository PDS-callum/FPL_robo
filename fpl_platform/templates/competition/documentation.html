Overview

The FPL Bot Competition allows you to create your own automated Fantasy Premier League bot that competes against other users' bots. Your bot will make decisions about transfers, captaincy, and team selection based on the data provided.

Bots are evaluated on their performance in the current FPL season, with rankings updated after each gameweek.

Requirements

Your bot must meet the following requirements:

  • Written in Python
  • Implement the required interface methods
  • Pass validation checks
  • Not use restricted imports or functions
  • Execute within reasonable time limits

Bot Interface

Your bot class must implement these two methods:

1. analyze(data)

Analyzes the current team and game state.

def analyze(self, data):
    """
    Analyze the current team and FPL data
    
    Parameters:
        data (dict): Contains current team, player stats, fixtures, etc.
    
    Returns:
        dict: Analysis results with insights and recommendations
    """
    return {
        'status': 'ok',
        'message': 'Analysis complete',
        'insights': []
    }

2. optimize(data)

Optimizes team selection and makes transfer decisions.

def optimize(self, data):
    """
    Optimize team selection and transfers
    
    Parameters:
        data (dict): Contains:
            - current_team: List of your 15 players
            - available_players: All FPL players you can transfer in
            - gameweek: Current gameweek number
            - bank: Money in the bank (in millions)
            - free_transfers: Number of free transfers available
            - chips_available: List of chips you can use this week
    
    Returns:
        dict: Transfer decisions and team lineup
    """
    return {
        'transfers': [],  # List of {out: player_id, in: player_id}
        'captain': player_id,
        'vice_captain': player_id,
        'lineup': [player_ids],  # 11 starting players
        'chip': 'wildcard'  # Optional: chip to use this week
    }

Using Chips

Your bot can use FPL chips to gain strategic advantages. Each chip can be used once per season.

Available Chips

Chip Name Variants Effect
Wildcard wildcard, wildcard_1 Make unlimited free transfers for one gameweek. Available twice per season (second one becomes available after GW20).
Bench Boost bench_boost, bb Points from your bench players are added to your total for one gameweek.
Free Hit free_hit, fh Make unlimited transfers for one gameweek only. Your team reverts to its previous state the following gameweek.
Triple Captain triple_captain, tc Your captain scores triple points instead of double for one gameweek.

How to Use Chips

Check which chips are available in the data parameter:

def optimize(self, data):
    chips_available = data.get('chips_available', [])
    
    # Check if wildcard is available
    if 'wildcard_1' in chips_available:
        # Good time to use wildcard
        return {
            'captain': best_captain_id,
            'vice_captain': vice_id,
            'lineup': starting_11_ids,
            'chip': 'wildcard'  # Activate wildcard this week
        }
    
    # Or use bench boost when you have a strong bench
    if 'bench_boost' in chips_available:
        # Check if bench is strong
        bench_quality = sum(p['predicted_points'] for p in bench_players)
        if bench_quality > 20:
            return {
                'captain': captain_id,
                'vice_captain': vice_id,
                'lineup': lineup_ids,
                'chip': 'bench_boost'
            }
    
    # Normal week - no chip
    return {
        'captain': captain_id,
        'vice_captain': vice_id,
        'lineup': lineup_ids
    }
Important:
  • Chips can only be used once (except Wildcard which has 2 uses)
  • The platform validates chip availability before applying it
  • If you request an unavailable chip, it will be ignored (no error)
  • Strategic chip usage can significantly boost your ranking!

Example Bot

Here's a simple example bot to get you started:

class SimpleFPLBot:
    """
    A simple FPL bot that makes basic decisions
    """
    
    def __init__(self):
        self.team = []
        self.budget = 100.0
    
    def analyze(self, data):
        """Analyze current team"""
        current_team = data.get('current_team', [])
        
        # Calculate team statistics
        total_value = sum(player.get('cost', 0) for player in current_team)
        
        return {
            'status': 'ok',
            'message': f'Team analyzed. Total value: £{total_value}m',
            'insights': [
                'Consider transfers for injured players',
                'Look for players with good fixtures'
            ]
        }
    
    def optimize(self, data):
        """Optimize team and make transfers"""
        current_team = data.get('current_team', [])
        available_players = data.get('available_players', [])
        gameweek = data.get('gameweek', 1)
        chips_available = data.get('chips_available', [])
        
        # Sort current team by predicted points
        sorted_team = sorted(
            current_team, 
            key=lambda x: x.get('predicted_points', 0),
            reverse=True
        )
        
        # Select captain (highest predicted points in team)
        captain_id = sorted_team[0]['id'] if sorted_team else None
        vice_captain_id = sorted_team[1]['id'] if len(sorted_team) > 1 else None
        
        # Select best 11 for lineup
        lineup_ids = [p['id'] for p in sorted_team[:11]]
        
        # Example: Use triple captain on a good week
        chip_to_use = None
        if 'triple_captain' in chips_available and gameweek == 10:
            # Use TC when your captain has great fixtures
            chip_to_use = 'triple_captain'
        elif 'bench_boost' in chips_available and gameweek == 20:
            # Use BB on a double gameweek (if you know about it)
            chip_to_use = 'bench_boost'
        
        result = {
            'captain': captain_id,
            'vice_captain': vice_captain_id,
            'lineup': lineup_ids
        }
        
        # Add chip if using one
        if chip_to_use:
            result['chip'] = chip_to_use
        
        return result

Testing Your Bot

Local Testing (Recommended First Step)

Use the Bot Tester to validate your bot before submitting:

python tools/bot_tester.py your_bot.py

The bot tester will check:

  • ✓ No restricted imports (network access, file system, etc.)
  • ✓ Required methods are present (analyze() and optimize())
  • ✓ Methods execute without errors
  • ✓ Return values are in the correct format
Pro Tip: The bot tester uses the same validation rules as the platform. If it passes locally, it will pass on submission!

Platform Testing Workflow

After local testing, follow these steps on the platform:

  1. Submit your bot for validation
  2. Run backtests on previous seasons to see how it performs
  3. Analyze the backtest results to identify weaknesses
  4. Iterate on your bot's strategy
  5. Activate when you're confident in its performance
Tip: Backtests help you understand how your bot would have performed on historical data without risking your competition ranking. Run multiple backtests on different seasons to evaluate consistency!

Security Restrictions

For security reasons, the following are not allowed in bot code:

  • File system access (open, file)
  • System operations (os, subprocess, sys)
  • Dynamic code execution (eval, exec, compile)
  • Module imports (__import__)
  • User input (input, raw_input)

Your bot runs in a sandboxed environment with access to:

  • Basic Python built-ins (list, dict, str, int, float, etc.)
  • Standard operations (print, len, range, sum, min, max, etc.)
  • Data structures and algorithms

Competition Rules

  • Each user can have one active bot per season
  • Bots are executed automatically each gameweek
  • Rankings are based on total points accumulated
  • Standard FPL rules apply (transfers, hits, chips, etc.)
  • Bots must complete execution within time limits
  • Code can be updated, but changes require re-activation
